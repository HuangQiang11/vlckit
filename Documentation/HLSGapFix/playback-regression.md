# 修复库验证记录

日期：2026-11-05。Xcode 27.1（27A9275）；原生测试运行在 macOS，播放集成实验运行在独立 iPhone 17e／iOS 27.0 模拟器。包装层来自本 fork 的 `6629ecb91e7e05e6b3fcbf77b17d0421cff37923`，内核来自 `005e69e67a8730f128e44bde68437fbb048cf45f`，应用原有 12 个补丁及 HLS 修复补丁。

两个内核切片均使用 Debug 配置，`config.h` 中 `NDEBUG` 未定义；未通过关闭断言实现测试通过。

## 编译与原生回归

- VLC `adaptive_test` 的 13 组入口通过，包括新增的 HLS 默认时长继承、小数时长保留、序号缺口估算、缺失默认时长和时间溢出用例。
- iOS 真机 arm64 内核、VLCKit 包装层归档通过。
- iOS 模拟器 arm64 内核、VLCKit 包装层归档通过。

## 真实播放集成实验

在 HiTV 的独立测试工程副本中绑定本次修复库，不替换共享 SPM 缓存。回环 HTTP 服务先确认 HLS 实际输出视频，再挂起下一次列表刷新，使用真实生成的 H.264 TS 分片与本地 MP4。

| 场景 | 结果 |
| --- | --- |
| 旧 HLS 请求 stop 后立即启动 MP4 | 通过；复现旧状态 stopping、isPlaying=false 时，新 MP4 已输出的重叠，证明此状态不足以判断释放完成。 |
| 等待旧 HLS stopped 后启动 MP4 | 通过；挂起期间不启动，旧引擎停止后 MP4 正常输出。 |
| 旧 HLS 停止超时 | 通过；0.5 秒等待超时不启动 MP4、不强制释放旧实例。 |
| HLS 播放期间窗口跳至序号 100 | 通过；请求了新窗口分片，视频输出继续推进，无断言退出。 |
| HLS stopping 期间窗口跳至序号 100 | 通过；MP4 从未启动，旧 HLS 正常停止，无原生断言。旧官方二进制在相同分片列表合并路径曾触发 SegmentList.cpp:133 的 duration 断言。 |

跳号窗口使用独立媒体分片，首帧 PTS 为 101.4 秒，原窗口为 1.4 秒；已核对相差 100 秒。不能把原窗口分片重复用于新序号，否则会引入时间戳回退，干扰继续播放验证。

本记录不代表所有格式、网络与频道兼容性均已验证。未运行真机播放交互；原始 HEVC 文件、快速返回／切项、后台恢复和实际频道由项目负责人真机验收。
